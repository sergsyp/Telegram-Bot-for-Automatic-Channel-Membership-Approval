# Telegram-бот проекта «Мир 1С»

Автономный Telegram-бот клуба и подкаста «Мир 1С». Работает на BotHost без обращения к OpenClaw или OpenAI.

## Пользовательские возможности

- `/start` и `/menu` открывают главное inline-меню;
- «Подкасты» — 11 сезонов, 55 основных и один специальный выпуск с описаниями, именами гостей и ссылками на исходные посты;
- «Все сезоны» выдаёт весь каталог одним действием, последовательными сообщениями по сезонам из-за лимита Telegram 4096 символов;
- поиск по части названия, темы, описания или имени гостя выводит подходящие выпуски из всех сезонов;
- под описанием выпуска в каталоге и поиске показываются последние доступные
  просмотры в формате `YouTube 1 240 | VK Видео 980 | RuTube 630 | Дзен 570 |
  Telegram 1 430 | Всего 4 850 просмотров`; площадки без собранного значения не
  выводятся;
- административная команда `/collection_status` показывает состояние последней
  загрузки статистики, длительность, успешные и ошибочные запросы, разбивку по
  площадкам, актуальность данных, последние ошибки и пять последних запусков;
- «Клуб „Мир 1С“» — описание и кнопка вступления;
- «Обо мне» — развёрнутая профессиональная биография и социальные сети;
- «Попасть на подкаст» — приём одного текстового предложения, сохранение в SQLite и пересылка Сергею;
- «Контакты» — MAX, Telegram и кликабельный адрес почты;
- автоматическое одобрение заявок на вступление через `ChatJoinRequestHandler`.
- закрытая команда `/stats` для администратора показывает события, уникальных
  пользователей, ошибки и популярные действия за 24 часа, 7 и 30 дней.
- ежедневный сбор публичных счётчиков выпусков по проверенным точным ссылкам
  в 23:50 мск с бессрочной историей и уведомлением администратора только
  после окончательной ошибки.

Во вложенных экранах есть возврат назад или в главное меню.

## Хранение данных

SQLite хранится в постоянном каталоге BotHost: `/app/data/bot.db`. Включены WAL и внешние ключи. Test и production используют отдельные контейнеры и отдельные базы.

Таблицы:

- `users` — пользователь и даты взаимодействия;
- `podcast_proposals` — предложения тем;
- `audit_log` — команды, переходы по меню, поисковые запросы и число найденных
  выпусков, отправка предложений, одобрения заявок, результаты операций и ошибки.
- `platforms` — расширяемый справочник площадок типов `video`, `audio`, `text`;
- `podcast_episodes` — выпуски с устойчивым внутренним ID и первым Telegram-постом;
- `episode_publications` — проверенные точные ссылки выпусков на площадках;
- `publication_latest_stats` — последние успешные значения;
- `publication_stats_history` — бессрочная ежедневная история;
- `stats_update_runs`, `stats_update_errors` — запуски и окончательные ошибки.

Ручной контрольный прогон в контейнере выполняется командой
`python run_stats_once.py`. Она использует ту же базу, адаптеры, повторы и
уведомления, что и ежедневное задание.
Быстрая проверка по одной публикации каждой поддерживаемой площадки:
`python probe_stats_collectors.py`.

Первоначально зарегистрированы YouTube, VK Видео, RuTube, Дзен Видео,
Яндекс Музыка, Telegram и MAX. Каждая площадка хранится отдельно; при чтении
данных показатели можно агрегировать по типу. Telegram-публикации создаются
из первого post ID автоматически. Остальные ссылки находятся скриптом
`discover_publication_links.py`, проверяются владельцем и только затем
добавляются в `publication_links.py`.

Сборщик делает до трёх коротких попыток, не загружает изображения и видео,
не запускает браузер и не использует ИИ. Последнее успешное значение при
ошибке не затирается. Публичные счётчики подтверждены для Telegram, YouTube,
RuTube и Дзен. Для VK Видео используется один лёгкий запрос `video.get` с
сервисным ключом приложения. Яндекс Музыка не публикует счётчик прослушиваний
отдельного выпуска, а у MAX пока нет стабильного публичного счётчика: эти
площадки имеют статус `unsupported`, ссылки сохраняются, но ежедневные запросы
и ложные аварийные уведомления для них не создаются.

Для дополнительных параметров события используется JSON-поле `details`, а
признак `success` отделяет успешные действия от ошибок. Индексы по дате,
действию и Telegram ID ускоряют отчёты. Существующая база обновляется
автоматически без удаления старых записей.

Резервное копирование базы пока не настроено.

## Переменные окружения BotHost

Секреты нельзя записывать в исходный код. В карточке бота откройте «Переменные окружения»:

```text
BOT_TOKEN=<токен от @BotFather>
ADMIN_CHAT_ID=127626487
DATABASE_PATH=/app/data/bot.db
VK_SERVICE_TOKEN=<сервисный ключ приложения VK>
```

`BOT_TOKEN` обязателен. `VK_SERVICE_TOKEN` обязателен для сбора VK Видео и
должен передаваться только через защищённое хранилище BotHost.
`ADMIN_CHAT_ID` по умолчанию равен Telegram ID Сергея `127626487`.
`DATABASE_PATH` по умолчанию `/app/data/bot.db`.

## Контуры и выпуск изменений

- `@sergsyp_test_bot` разворачивается из ветки `test`;
- `@sergsyp_bot` разворачивается из ветки `main`;
- порядок: изменение в `test` → тестирование → обновление README → merge в `main` → production.

Любое изменение кода, поведения, команд, настроек, структуры или деплоя требует одновременного обновления README.

## Локальная проверка

Требуется Python 3.11+.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
BOT_TOKEN='123456:local-test-token' python -m unittest -v
```

Поиск ссылок-кандидатов (CSV выводится в терминал и требует проверки):

```bash
python discover_publication_links.py
```

Запуск:

```bash
export BOT_TOKEN='<токен>'
export ADMIN_CHAT_ID='127626487'
export DATABASE_PATH='./data/bot.db'
export VK_SERVICE_TOKEN='<сервисный ключ приложения VK>'
python main.py
```

## Развёртывание

BotHost собирает `Dockerfile`, устанавливает `requirements.txt` и запускает `python main.py`. Бот должен быть администратором целевой группы с правом одобрять заявки.

## Безопасность

- токены хранятся только в переменных окружения BotHost;
- `.env`, SQLite и содержимое `/app/data` не коммитятся;
- предложения содержат Telegram ID, имя и username пользователя и доступны администратору;
- журнал содержит Telegram ID и поисковые запросы, доступен только владельцу
  контейнера и через закрытую команду администратора `/stats`;
- при утечке токен перевыпускается через @BotFather.
